# Flock: mixed-provider collaboration

The active checkout is `C:/Dev/superset`, branch `windows-port`. Existing native
Claude and Codex managers own conversations. The authenticated mobile session API
already reaches both, but its in-memory request ledger and inconsistent busy
semantics are not a team coordinator. The current essay connection is peer-led;
adding a coordinator to a new group must not retroactively change that relationship.

## First release

- Local, durable groups of 2–6 real sessions, with a chosen coordinator, shared brief,
  success criteria, responsibilities, tasks, decisions, versioned text artifacts,
  and an inspectable exchange journal. Existing conversations retain their names.
- Native session adapters, and a development adapter to the already-enabled local
  API so the first live test needs no app restart. No duplicate CLI resume process.
- Persist-before-send outbox; one delivery per recipient; busy/input/error gates;
  bounded sends and concurrency. Ambiguous delivery after a crash is held for user
  inspection, never retried automatically. Restarted groups resume only explicitly.
- A small, validated final-response protocol permits peer messages, assignments,
  artifact review, decisions and completion in already-running sessions without
  replacing their tools or credentials. Sender identity comes from the correlated
  native conversation, not from model-supplied fields. Peer messages confer no new
  permissions. No arbitrary commands or file paths are executed by this protocol.
- Event-driven updates, bounded retry/backstop polling only while a group runs.
  Shared-folder turns serialize; existing separate worktrees can run concurrently.
- UI: a readable brief, compact coordinator/team composition, actual exchange links,
  task and artifact focus, native-conversation access, user intervention, pause,
  resume, stop and explicit completion evidence. Dracula tokens, reduced motion.

## Verification

Implemented and verified queue ordering, failure/restart ambiguity, identity
mismatch, unrelated user turns, atomic responses, resource limits, folder
serialization, pause/resume and completion with deterministic adapters. A live
Codex coordinator and Claude reviewer completed a fresh tool-library brief in five
deliveries, including a requested revision and a second independent review. The
existing essay conversations were busy and were preserved; dedicated real sessions
provided the test. A one-time native Claude naming permission was approved only
after the user explicitly allowed that action.

The user chose Flock as the product name and requested Swarm-inspired native UI.
The updated design uses a compact native toolbar and Mission / Roster / Launch
setup with presets, editable roles, existing or dedicated sessions, shared
references and actual working agreements. The same React components run in the
sidebar demonstration and the native route. UI checks cover narrow layouts,
keyboard navigation, references, revision reviews and reduced motion. Exact
evidence boundaries and commands are in `docs/flock.md`. Commit completed source;
no installer, version bump or publication is requested for this task.
