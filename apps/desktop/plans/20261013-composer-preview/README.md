## Implementation boundary

The user accepted the composer and activity layout on 2026-10-13, with the explicit requirement to preserve the existing effort, model and permission menu UI. The preview now imports those production controls rather than substituting simple demo menus. The optional split triggers do not change the current shipped composer by default. The full composer and activity overlay still need production wiring before an installer is built. The mic demo inserts sample text only. `C:/Dev/Flow` contains the user's C# WinForms dictation app; its current `Program.cs` uses a single-instance mutex, and `FlowContext` exposes capture only through hotkeys. `--open` opens settings; it does not start dictation. Real integration needs an explicit local start/stop command to the existing Flow process, readiness/error responses, and focus restoration to the composer. Do not emulate a held global shortcut, launch duplicate instances, or record automatically.

The question-card bug fix is separate production code in `question-choices.ts` and `session-manager.ts`. It recovers the supplied caliper question despite the follow-up sentence, restores pending inferred replies on reconnect while keeping dismissed replies suppressed, and handles completed streamed turns without a separate completed-message payload. Structured question tools remain preferred; a fallback only offers explicit reply options and never sends an answer automatically.

Receipts/screenshots go to `.tmp/composer-20261013-qa`. These are source-preview checks, not installed-app verification.
