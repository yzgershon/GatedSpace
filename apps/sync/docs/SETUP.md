# Dedicated GatedSpace Sync service

This is a separate account and encrypted checkpoint service. It does not replace
the desktop's local workspace database or the Tailscale mobile bridge. The desktop
transfer workflow lives in Settings > Account > GatedSpace Sync. It pairs each PC
separately, protects its credentials with the OS vault, and transfers selected
conversations with their Git working files. Physical two-PC verification is still
required for an installed release; local fixtures are not OMEN hardware evidence.

## Deployment

The service uses Next.js, Better Auth's Drizzle adapter, a dedicated Neon database,
and **private** Vercel Blob storage. Use a new Vercel project, with `apps/sync` as its
root, `bun install --frozen-lockfile` as the install command and `bun run build` as
the build command. Use the existing free plans unless the owner authorizes a change.

`bun apps/sync/scripts/stage-deployment.mjs` creates a fresh, isolated upload folder
and a source manifest under the repository's ignored `.tmp` directory. It copies
only the required service source, protocol, schema and configuration. From that
folder, run `bun install --ignore-scripts`, link the dedicated project and deploy.
Never deploy the broad working directory or copy desktop `.env` files into it.

Required environment names are listed in `../env.example`. Use a randomly generated
authentication secret and the same stable HTTPS origin for OAuth callbacks and
device authorization. `SYNC_ALLOWED_EMAILS` is an explicit comma-separated list;
new users must have a verified email in that list. Never put secret values in this
document, source control, shell command arguments, or chat.

## Initial database setup

The complete schema is `packages/db/src/schema/continuity.ts`. All tables are in the
dedicated `continuity` schema: users, sessions, accounts, verifications, device codes,
rate limits, devices, streams, checkpoints, objects and quotas.

The repository's `AGENTS.md` prohibits agents from running migrations and requires
an isolated Neon branch. Until the owner explicitly authorizes an exception, the
owner must perform these steps:

1. Create a new Neon branch named `sync-initial-schema` in the dedicated project.
2. Set `DATABASE_URL_UNPOOLED` locally to that branch's direct connection string,
   using a protected environment file. Do not replace another application's URL.
3. From `apps/sync`, run `bun x drizzle-kit generate --config drizzle.config.ts
   --name initial_continuity` and review the generated migration.
4. Apply it to the test branch with `bun x drizzle-kit migrate --config
   drizzle.config.ts`. Verify the auth adapter, account isolation and concurrent
   revision checks against real Postgres.
5. Apply the reviewed migration to the dedicated service database only after owner
   confirmation. No existing desktop/workspace database is a migration target.

Migration files must be generated by Drizzle, never edited manually. The initial
migration is included in `drizzle/0000_initial_continuity.sql`. Its eleven tables
were verified on an isolated Neon branch before applying the same migration to
the new dedicated database, with the owner's explicit authorization. This does
not authorize migrations against another database. `/api/health` returns 503 until configuration, required schema and
at least one sign-in provider are present; a successful `select 1` is insufficient.

## OAuth application registration

Create dedicated applications named **GatedSpace Sync**, not copies of AI-provider
credentials. Set the homepage to the service's stable HTTPS origin. Register:

- GitHub callback: `<SYNC_ORIGIN>/api/auth/callback/github`.
- Google authorized redirect: `<SYNC_ORIGIN>/api/auth/callback/google`.
- Google authorized JavaScript origin: `<SYNC_ORIGIN>`.

Store the resulting client IDs and secrets as the matching project environment
variables. Keep Google in testing and add the owner as a test user until a broader
release is intentional. Authentication alone does not transfer conversations or
files. Each computer still signs in to its own Codex/Claude provider account.

## Transfer protocol and boundaries

- The client encrypts a checkpoint with AES-256-GCM before any upload. The recovery
  key is a random 32-byte value and is never sent to this service.
- Authenticated encryption binds account, session, checkpoint ID and chunk order.
  Each opaque object also has a SHA-256 digest and checked length.
- A revision check and expiring lease with a monotonically increasing number stop
  an old writer from publishing over newer work. Retrying the same committed
  checkpoint is idempotent. Divergent work must be preserved as a separate session.
- Current limits: 256 MiB per checkpoint and 1 GiB per account. Uploads are bounded
  to 512 KiB chunks. These are application limits, not a promise of unlimited free
  hosting. Old/pending objects are retained; garbage collection is not implemented.
- Project paths reject traversal, Windows special files and common credential
  locations. The desktop collects only the explicitly selected Git root, not a broad folder
  containing unrelated work. Common credential files and ignored files are excluded.

## Desktop workflow

1. Open Settings > Account > GatedSpace Sync. Connect and approve the matching
   device code through Google or GitHub on the private service.
2. On the first PC, create a recovery key and save its protected backup. On the
   other PC, connect the same account and enter that exact key. It never goes to
   the service. Account connections currently expire after 30 days; reconnecting
   preserves the local recovery key and queued work.
3. Select a finished Codex or Claude conversation and its specific Git project.
   This enables completed-turn checkpoints, checked once per minute while the
   desktop is running. Use Sync now and wait for its upload confirmation before
   turning off this PC. Disable Auto-sync to pause new checkpoints.
4. On the other PC, refresh available conversations and restore into a **new**
   folder. Open the imported conversation from Recent sessions. Install project
   dependencies and sign into each AI provider on that PC independently.
5. If both PCs changed the same checkpoint, uploads pause for that conversation.
   Restore the remote version into a separate folder. The old local session,
   project and encrypted queued snapshot are retained; select the old conversation
   again to upload it as a separate stream.

Restores create a fresh Git root; they do not copy Git history, hooks, provider
credentials, global skills, or ignored files. Existing project folders are never
merged or overwritten. Root HANDOFF.md must be tracked or explicitly moved by the
owner if it is ignored. Native conversation history remains in the transferred
transcript. Codex parent histories are materialized before legacy replay; live
SQLite/WAL databases and cloud-only in-memory imports are never copied. Each
restored native session has a new local ID. Source files are limited to 128 MiB per
checkpoint and 16 MiB per file; images to 64 MiB total. The full encrypted payload
must fit the protocol limit. Quota failures retain local work and queued uploads.

## Verification

Run `bun test apps/sync/src/server packages/shared/src/continuity` at the root,
`bun run --cwd apps/sync typecheck`, `bun run --cwd apps/sync build`, and root lint.
Verify the isolated staging build too: it must not depend on unrelated packages in
the monorepo's node_modules. Inspect the deployed page, disabled-provider states,
health response, unauthenticated endpoints and cache/security headers.

HTTP tests use simulated object storage. The opt-in `scripts/verify-database.ts`
also checks the real Better Auth adapter and Postgres transactions on an isolated
branch: verified account linking, encrypted provider tokens, device approval,
account isolation, competing leases, idempotent checkpoints, and concurrent quota
limits. It creates synthetic records and removes those records afterward.

The protected test environment must contain `DATABASE_URL_UNPOOLED`,
`SYNC_TEST_BRANCH`, `SYNC_TEST_HOST`, and `SYNC_MAIN_HOST`. Pass the environment
file path, expected test host and receipt path as arguments. It refuses the main
host and invalidates any previous receipt before beginning. Do not run it against
production or use a real user's identity for synthetic tests.

Verification in September 2026 also exercised real Google and GitHub browser
sign-in against the dedicated service, a private Blob round trip with synthetic
bytes, and Windows safeStorage plus owner-only DACLs. Desktop tests cover two
isolated profiles, interrupted uploads, lost commit responses, revision conflicts,
project restore and attachments. Native Codex replay and native Claude resume were
verified with synthetic histories (Claude used a loopback mock model). The actual
settings components passed browser tests at 980, 560 and 360 pixels. No real user
transcript or project was uploaded during these tests. Physical OMEN, Android, and
cold-reboot verification remain separate installation checks.

The local welcome screen opens the existing computer workspace. Hosted Google/GitHub
sign-in is reached from Settings > Account > GatedSpace Sync; it does not replace
the local workspace database or its login session.
